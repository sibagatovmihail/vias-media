Found by hand and fixed in this round (axe cannot see either):

- **Text over the pricing glow.** On phones the "[ Preise ]" label sat on the bright part of the image:
  2.5:1. The image is now 1/0.6 as tall as the space above the text, so text starts below the bright band.
  Measured against the rendered background, worst pixel under each element, at 320 / 393 / 768 / 1024 / 1440:
  label 6.7–7.8:1, title 8.9–14.9:1, paragraph 9.8–10:1.
- **Focus hidden by pinned sheets (2.4.11).** Tabbing to a project button could leave it under the next
  card; tabbing into the pinned pricing block could leave the first button below the screen. `revealFocus()`
  in `main.js` now scrolls until the focused control is on screen and not covered. Test: 46 Tab presses from
  the top at 1440×900 and 393×852, each stop checked for position and for what `elementFromPoint` returns:
  all visible. (One stop, a two-line text link, is flagged by the test only because its corner lies outside
  the inline box.)
- **Footer link not clickable.** The giant `vias.` wordmark's line box reached over "Webagentur
  Neubrandenburg" at 1440px and took its clicks. The wordmark is decorative and now has
  `pointer-events: none`.

Decorative and hidden from assistive tech: the ghost word "Projekte", the blurred project backdrops
(`alt=""`), the word mask and its photograph (`aria-hidden`), the pricing glow (CSS background).

## All other pages (2026-10-09)

Services, projects, five case studies, contact, the Neubrandenburg landing page, Impressum, Datenschutz, blog

axe-core 4.14.0, same rule tags, eleven pages (services, projects, two case studies, contact, landing page,
Impressum, Datenschutz, blog index, one article, homepage), each at 1440×900 German with full motion and at
390×664 English with reduced motion: **22 runs, 0 violations** after one fix:

- Tables in articles scroll sideways on phones but could not be focused (`scrollable-region-focusable`).
  `main.js` now gives a table `tabindex="0"`, `role="region"` and a label whenever it actually overflows.

Contact form, tested with the form service's address intercepted (nothing was sent), at 1440×900 and 393×852:

- Own validation instead of browser bubbles: name and e-mail required, phone checked if filled. The message
  sits in the gap under its field; the form's height is the same before and after (729.3px / 951.2px), also
  when "could not send" is shown. Focus moves to the first invalid field; fields carry `aria-invalid` and
  `aria-describedby`.
- Dropdown is a listbox: opens with Arrow Down, arrows / Home / End / first letter move, Enter chooses, Esc and
  click outside close, focus returns to the button; the hidden input carries the value; the list is scrolled
  fully on screen when it opens.
- Send failure: message in the reserved line, typed text is kept. Success: dialog with focus on its button,
  Tab stays on it, Esc closes, the page behind is `inert` and pinned, the scroll position is restored (300 →
  300), focus returns to the send button.
- Bug found by this test and fixed: after closing any overlay on a pointer device the page jumped to the top,
  because the smooth scroller had measured the pinned page (one screen high).

Other points:

- Current page in the header: `aria-current` plus a filled block (not colour alone).
- Case-study gallery: a focusable, labelled region that scrolls with the arrow keys; two labelled buttons.
- Page hero taller than a small screen (320×568): it pins by its bottom edge, the second button and the extra
  line are dropped there, so the main action stays on the first screen.
- Page change uses native view transitions; switched off under `prefers-reduced-motion`.

## Keyboard

- Skip link appears on first Tab and jumps to `#main`.
- Visible focus ring (2px ink outline) on links, buttons, accordion triggers.
- Projects are a plain list of four links; focus is kept clear of the pinned cards (see third round).
- Header links are split into letters for the roll effect; each link carries its full name as `aria-label` and the letters are `aria-hidden`.
- Service rows show their drawing on keyboard focus as well as on hover; the drawings are decorative (`aria-hidden`).
- Menu sheet: opens/closes with the button, closes with Esc and returns focus; the page behind is `inert`.
- FAQ: buttons with `aria-expanded` / `aria-controls`; one panel open at a time.
- The custom cursor hides and the native one returns on Tab.

## Motion

`prefers-reduced-motion: reduce` switches off: smooth scrolling, every pinned block (hero, project cards,
pricing: all become plain flow), the horizontal "So arbeite ich" scene and the word mask (it becomes a ruled
list; the photograph is never loaded), the hero lines driving apart, the gliding project screenshots, the
converging footer headline, the letter roll in the header, line reveals, the ink-fill statement, and the
cursor label lag. Checked at 1440×900 and 393×852: nothing pinned, nothing hidden.
